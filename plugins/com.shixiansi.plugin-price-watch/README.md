# 网页变化监控（com.shixiansi.plugin-price-watch）

盯住几个网页（商品价格、库存、公告页）：**变了才说一句**，并把「哪一段变了」记下来。

- **桌宠那边**：一个不显示的常驻帧。它按你定的间隔抓取、比对内容指纹，内容真的变了就让桌宠
  弹一句话（气泡）。
- **控制中心**：这张插件页只做两件事——显示每条的状态与变化历史、把设置交给宿主的设置表单。
  它不抓取、也不弹气泡。

## 说清楚一件事：`netHosts` 里那个 `example.com` 是占位

宿主的 `net.fetch` 只连**声明过的**域名，而插件清单是**静态**的、写死在包里——插件没法在
运行时说「我现在要连一个新的站」。一个"监控任意网页"的插件显然不可能把所有站都写进清单。

所以这个插件的域名白名单由两部分拼起来：

| 来源 | 内容 |
| --- | --- |
| `manifest.netHosts` | `["example.com"]` —— **纯占位**，只为了让这份清单能通过"声明了 `net.fetch` 就必须有白名单"的校验。它不代表这个插件真会去连 example.com |
| 设置项「监控条目」（`hostWhitelist: true`） | **这才是它真正会连的域名**。宿主会在每次 `net.fetch` 前，把你这一项里的**当前值**按 URL 解析出 host 加进白名单 |

也就是说：**第一项设置里写进去的域名，才是它真正会连的站**。你把条目填成
`https://item.jd.com/100012043978.html`，白名单里就有 `item.jd.com`；你没写过的站，它连不上、
也拿不到数据（宿主会回「net.fetch 的域名未声明」，界面把这句话原样显示）。

## 它要的权限（4 项）

| 权限 | 为什么 |
| --- | --- |
| `net.fetch` | 抓页面。域名来自上面那条规则（`manifest.netHosts` ∪ 设置里的条目） |
| `storage` | 每条监控的快照（内容指纹 + 一小段摘录）与最近 20 次变化 |
| `plugin.config` | 条目、间隔、免打扰起止 |
| `pet.bubble` | 「变了说一句」的那个气泡。它只在桌宠里被服务——所以这句话由常驻帧说，插件页不说 |

没有 `events`、没有 `process`、没有随包脚本：它只发 HTTP 请求。

## 设置

| 项 | 说明 |
| --- | --- |
| 监控条目 | 一行一条：`名字 | URL | CSS 选择器`。第三段可空（空着就比对整页正文）；最多 8 条；`#` 开头的行会被跳过 |
| 抓取间隔（分钟） | 默认 60，**最小 15**（低于 15 会被夹到 15——1 秒轮询是反模式，不是配置项） |
| 免打扰开始 / 结束 | `HH:MM`，默认 `22:00` / `08:00`。**可以跨午夜**；这段里只更新快照、不弹气泡 |

## 它怎么判断「变了」

1. **取内容**：抓回来的 HTML 先按选择器缩到你那一块（没写选择器就整页）；然后去掉
   `<script>` / `<style>` / `<noscript>` / `<template>` 与 HTML 注释，把连续空白（含全角空格、
   零宽字符）折成一个空格。不做这一步的监控器第一天就报警——时间戳、埋点 id、模板缩进每天都在变。
2. **算指纹**：对那段字算一个 16 位十六进制的内容哈希（`lib/extract.js` 末尾）。比对**不存两份全文**：
   快照里只有指纹 + 一段 ≤160 字的摘录。
3. **首次抓取只建基线**，一条气泡都不发。
4. **变化要连续两个间隔都抓到同样的新内容才播报一次**（去抖）。代价是"变了"晚一个间隔才说；
   换回来的是：构建中/AB 分桶那种短暂变化不会响，而 A→B→A→B 一直横跳的页面一个气泡都不会有。
   基线更新之后，同样的内容不再算变化——所以「变了」只说一次。
5. **抓不到就保留旧快照**：网络失败、`4xx/5xx`、选择器没命中、正文是空的——这些都只记一条
   `ok:false`（带原因），旧的指纹与「上次成功的时间」原样留着，插件页照常显示
   「上次成功是 23 分钟前」。
6. **免打扰时段**：照常抓、照常更新快照，**只是不弹气泡**。如果这段里连快照都不更新，第二天
   早上会攒下一串"变化"一次性炸出来。

## 改设置什么时候生效

抓取的计时器住在桌宠进程里，而设置是在控制中心保存的。两条路都用上了：

- 插件页收到 `config.changed`，就把一个时间戳写进 `cmd/reload`（`storage.changed` 是 `storage`
  权限自带的推送，不需要 `events`）；常驻帧收到之后**清掉旧计时器、按新间隔重排**——所以改了
  间隔不用等旧周期走完。
- 兜底：每一轮抓取开始都重读一次设置。信标丢了（例如桌宠当时没在跑），下一轮自己会接上。

## 已知边界

- **脚本渲染的站抓不到内容**：`net.fetch` 拿的是 HTML 原文，不会执行页面里的 JS。这类站要么换一个
  出现在 HTML 里的选择器，要么换一个数据接口（JSON 也可以监控——它同样是一段文本）。
- **8 MiB 截断**：宿主的响应体上限是 8 MiB，超了会截断（`truncated: true`）。截断的正文照样比对，
  但页面尾部看不见。
- **最多 8 条**、每条一个请求：间隔 15 分钟、8 条 = 每小时 32 个请求。别把它当成爬虫。
- **只看内容，不看状态码以外的元数据**：`ETag`/`Last-Modified` 不用（宿主没有暴露条件请求）。

## 自检

在 `market/` 里跑这两条：

```powershell
node docs/plugin-testkit/plugin-check.mjs plugins/com.shixiansi.plugin-price-watch
npx vitest run tests/plugin-price-watch.test.js
```

行为测试（`market/tests/plugin-price-watch.test.js`）钉住的六件事：首次抓取不报警、变化只报一次、
横跳被去抖吃掉、未配置一条请求都不发、抓不到不覆盖旧快照、免打扰跨午夜时只更新快照。
