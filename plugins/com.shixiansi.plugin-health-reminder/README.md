# 健康提醒（久坐 / 喝水 / 护眼）

三条最普通的健康提醒，住在桌宠里。

| 提醒 | 默认间隔 | 说话的样子 |
| --- | --- | --- |
| 久坐 | 45 分钟 | 已经坐了 45 分钟，起来动一下 |
| 喝水 | 60 分钟 | 该喝水了（60 分钟一次） |
| 护眼 | 20 分钟 | 看一眼 6 米外，数 20 秒（20-20-20） |

- **到点只说一次**：判定用"上一次说的时间 + 间隔"，不累加计数——机器休眠两小时回来，下一拍
  立刻知道"早该说了"，而不是从零再数。
- **头顶徽标**（`pet.badge`）显示下一条还剩几分钟；三条都关掉时写"已停"。
- **关掉哪一条就立刻停**：宿主推一条 `config.changed` 过来，这一拍就不再说话，徽标随之更新。
- **免打扰**：默认 `22:00 – 08:00`（跨午夜）。这一段里到点的提醒**直接跳过、不补发**，
  否则 08:00 一出门会连发三条。
- **跨日**：过了本机 **04:00** 才算新的一天，当天的"已提醒次数"从这里清零（和待办/习惯同一套
  切日规则）。凌晨两点的那杯水仍算前一天。
- **「今天先别提醒我」**：浮层卡片上那个按钮写的是**日期**本身，所以它第二天自动作废，
  不需要谁来清它。

## 三个落点

| 落点 | 内容 |
| --- | --- |
| `pet.badge` | 头顶一行：`护眼 15 分` / `免打扰中` / `今天不提醒` / `已停`（≤16 字符） |
| `surface`（280×112） | 三条各自的"还剩几分钟" + 「今天先别提醒我」 |
| `workshop` | 控制中心插件页：下一次、今天说了几次、免打扰被认成几点、以及**这个插件做不到什么** |

## 做不到的事（写在界面上，不假装做到）

**全屏时不打断**：宿主今天没有全屏检测这个能力——没有对应的方法，也没有对应的事件。申请
`process` 去读前台窗口、或者写 sidecar 去轮询，都不是这个插件该付的代价。所以这一轮用**免打扰
时段**兜住：全屏里会不会弹，取决于那一刻在不在免打扰里。要真正做对，得等宿主提供全屏 / 前台
窗口的机制。

## 没有授予 `events` 会怎样

宿主只在 `granted` 里有 `events`（或 `net.ws` / `net.fetch` / `plugin.call`）时才给插件挂常驻帧
（`frontend/src/main.js` 的 `backgroundPlugins`）。所以：

- 授予了 `events`：常驻帧跑钟，**关掉界面也在提醒**（这是正常形状）；
- 没授予：没有常驻帧，浮层面自己跑钟——**提醒只在那块卡片开着时生效**；
- `events.subscribe` 被拒：提醒照常（它靠的是钟表，不是事件），只是设置改动要等下一拍
  （≤30 秒）——那一侧会自己重读设置。

控制中心不服务 `events.subscribe`，但宿主会把 `config.changed` **直接推**给插件，所以
workshop 那一页改设置是立刻生效的。

## 文件

```
manifest.json      权限：events / pet.surface / pet.bubble / plugin.config / storage
panel.html         三副面孔共用一个文档（由 init.surface 决定）
app.js             接线：钟（30 秒一拍）、事件、谁跑钟（isTicker）
lib/schedule.js    纯函数：免打扰、切日、到点判定、徽标文字（用例直接喂时间戳）
lib/core.js        宿主桥、私有数据的读/写、每页共用的 DOM 引用
lib/surface.js     那张 280×112 的卡片
lib/workshop.js    控制中心那一页（只读）
style.css          自带调色板（声明了浮层面，不引 ui.css）
```
