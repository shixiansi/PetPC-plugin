默认渠道

不点名的调用（绝大多数）走这一个。多个渠道时按 id 排序挑"第一个就绪的"是宿主的老规则—— 在这里选一个，就不用依赖那个规则。

它是怎么被用掉的

  1. 消费方（对话、QQ、记忆核心……）申请了 llm.borrow 时，自己没配置就借这里。
  2. 一个渠道的密钥可以有多个：宿主用**第一个已保存的**；某个 key 欠费了，删掉或换成下一个即可。
  3. 每天请求上限按调用方算，不在这里——渠道不分流别人的额度。
  4. 渠道地址也要过 net.fetch 的白名单：保存时这一页会把新地址自动加进 「额外允许的地址」，这样你不必手抄域名。
