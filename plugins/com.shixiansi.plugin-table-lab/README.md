# 表格分析（com.shixiansi.plugin-table-lab）

拖一份 CSV 进插件页：推断每列的类型、按一列做分组计数、用 SVG 画一张条形图；
桌宠旁边那张 300×150 的卡片显示「当前表格 · N 行 × M 列」与一行分组结论，并能在那里点
「让模型解读」。

## 两件事值得先说清楚

**一、模型只在卡片上。** `llm.chat` 只在桌宠那个程序里被服务，控制中心的插件页（`slot:
"workshop"`）不服务它（`docs/plugin-dev.md` §9）。所以插件的落点是两个：`panel: true`
铺整页 + 一块 `surface` 卡片。工坊页里那个位置是一行说明，不是一个点了会失败的按钮——
在 workshop 里硬发 `llm.chat` 换来的只会是宿主日志里一行「本程序不支持该方法」。

**二、文件只经 FileReader。** 宿主从不把磁盘路径交给插件，用户拖进来的那个 `File` 就是全部
输入。源码里没有 `process.*`、没有任何绝对路径、也没有第二种读法；GBK 靠
`FileReader.readAsText(file, 'gbk')`，插件自己不解码。

## 权限

| 权限 | 用来做什么 |
| --- | --- |
| `storage` | 把"当前表格"的摘要（结论，不是整张表）写给卡片读：`summary/current` |
| `plugin.config` | 读三项设置：预览行数、字段分隔符、默认字符集 |
| `llm.chat` | 卡片上那个「让模型解读」按钮 |
| `pet.surface` | 那张 300×150 的卡片本身就是它：宿主打开浮层面的那一刻**硬判**这一项，没申请就永远点不开 |

没有 `process`（不启动本机程序）、没有 `pet.bubble`（结论写在卡片上，不需要桌宠再喊一嗓子
——申请了却不调用的权限就是让用户在安装对话框里多答一个什么也不做的开关）。

> **声明了 `surface` 就必须申请 `pet.surface`。** 这一对是宿主两处代码各自判的：manifest
> 校验（`internal/plugins/manifest.go`）不看这一项，而 `OpenPluginSurface` 在
> `app_plugin_surface.go` 里判。两边不一致的后果是"装得上、点不开，也不报错"——
> `tests/plugin-table-lab.test.js` 里有一句断言专门钉这条规矩。

## 界面上的三条诚实

- **截断会说**：超过预览行数（默认 200）就只统计前 N 行，界面与卡片都写明"只统计了前 N 行
  （文件里共 M 行）"。
- **喂给模型的是摘要**：行列数、列类型、分组计数。整张表既没有意义（`llm.chat` 的 `text`
  上限 4000 字符），也不该离开这一页。
- **空单元格不算类型证据**：一列里有空格仍然可以是整数列；整列全空标成"空列"，不猜类型。

## 样式

这个插件声明了浮层面，所以**不整份引 `ui.css`**（§8.6 末尾那条例外：kit 的阴影与 hover
位移在矩形裁剪下会被切掉）。`style.css` 自带一份调色板，色值只出现在 `:root` 与
`html[data-theme='light']` 两个块里；没有 `box-shadow` / `filter` / `transform`。
